# «Напомни, когда выходить» — дизайн

Дата: 2026-10-24 · Ветка: `dev`

## Цель

Сейчас подписка присылает расписание маршрута в фиксированное время, и пользователь сам высчитывает, когда выходить. Новый режим подписки делает это за него: пользователь говорит «готов выйти к 8:00, до остановки идти 10 минут», а бот каждый подходящий день находит первый рейс не раньше 8:00 и пишет ровно тогда, когда пора выходить.

Старый режим остаётся. Существующие подписки продолжают работать без изменений.

## Решения

| Вопрос | Решение |
|---|---|
| Сценарий | Ежедневное напоминание «к моему времени» |
| Старая подписка | Остаётся вторым режимом (`schedule`) |
| Дни | Каждый день / будни / выходные — для обоих режимов |
| Какой рейс | Первый с отправлением **не раньше** целевого времени |
| За сколько предупреждать | Кнопки 5 / 10 / 15 / 20 / 30 минут |
| Как узнать рейс | Планировать за 60 минут до целевого времени (вариант A) |
| Подписок на маршрут | Одна; режим переключается в её настройках |

Отклонённые варианты расчёта рейса:
- опрашивать сайт каждую минуту перед целевым временем — 30–60 запросов на одно напоминание к и так медленному сайту;
- вычислить рейс один раз при настройке — врёт в выходные и при изменении маршрута.

## 1. Модель данных

### `subscriptions` — новые колонки

Добавляются через `ALTER TABLE` в `create_tables()`, как уже сделано для `statistics`:

| Колонка | Тип | Значения | По умолчанию |
|---|---|---|---|
| `mode` | TEXT | `schedule` / `remind` | `'schedule'` |
| `days` | TEXT | `all` / `weekdays` / `weekends` | `'all'` |
| `lead_min` | INTEGER | 5, 10, 15, 20, 30; только для `remind` | `NULL` |

`notify_time` (`ЧЧ:ММ`) сохраняет смысл для `schedule`, а для `remind` означает целевое время «готов выйти к». Дефолты дают старым подпискам прежнее поведение — миграция данных не нужна.

### `reminder_runs` — новая таблица

```sql
CREATE TABLE IF NOT EXISTS reminder_runs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sub_id INTEGER,
    user_id INTEGER,
    day TEXT,          -- YYYY-MM-DD
    fire_at TEXT,      -- ЧЧ:ММ, когда отправить
    dep_time TEXT,     -- ЧЧ:ММ отправления выбранного рейса; NULL если рейсов нет
    route TEXT,        -- номер маршрута выбранного рейса
    next_dep TEXT,     -- ЧЧ:ММ следующего рейса; NULL если нет
    status TEXT,       -- planned / sent / skipped
    UNIQUE (sub_id, day)
)
```

`UNIQUE(sub_id, day)` защищает от повторного планирования, в том числе после перезапуска. При каждом планировании удаляются записи старше 2 дней. При удалении подписки или маршрута удаляются и её записи. При изменении подписки удаляются все её записи — следующая минута спланирует заново по новым настройкам.

## 2. Сценарий настройки

Вход прежний: `/favorites` → маршрут → «🔔 Подписаться». Сначала шаги с кнопками, текстовый ввод — последним.

**Шаг 1 — режим**

> **🔔 Как присылать?**
>
> **📋 Расписание в заданное время** — каждый день в выбранное время бот пришлёт расписание этого маршрута. Удобно, если хочешь сам посмотреть ближайшие рейсы.
>
> **🚶 Напомнить, когда выходить** — укажи, к какому времени ты готов выйти и сколько идти до остановки. Бот сам найдёт первый рейс после этого времени и напишет ровно тогда, когда пора выходить, плюс подскажет следующий рейс на случай, если не успеешь.
>
> `[📋 Расписание]` `[🚶 Напоминание]` `[Отмена]`

**Шаг 2 — дни:** `[Каждый день] [Будни] [Выходные]`

**Шаг 3 — только для `remind`:** «За сколько минут предупредить? (сколько тебе идти до остановки)» `[5] [10] [15] [20] [30]`

**Шаг 4 — время текстом** (существующий `_parse_time`):
- `schedule`: «Во сколько присылать расписание?»
- `remind`: «Во сколько ты готов выйти? Я найду первый рейс не раньше этого времени.»

**Подтверждение**, например: «✅ По будням напомню за 10 мин до первого рейса после 8:00.»

Для `remind` после сохранения бот сразу запрашивает сегодняшние рейсы от целевого времени на 60 минут. Если их нет, к подтверждению добавляется: «⚠️ После 8:00 в течение часа рейсов не нашлось — проверь время». Если сайт не ответил, предупреждение не показывается.

**Существующая подписка** — экран управления показывает сводку («🚶 Будни, 8:00, за 10 мин» / «📋 Каждый день, 7:30») и кнопки `[✏️ Изменить]` (заново шаги 1–4, заменяет «Изменить время»), `[🔕 Отписаться]`, `[🔙 Назад]`.

Кнопка подписки на экране маршрута показывает режим: «🔔 Подписаться» / «📋 Расписание 7:30» / «🚶 Напоминание 8:00».

**Отмена** на любом шаге возвращает к экрану маршрута (как текущий `sub_back_`). Если данные FSM потеряны после перезапуска — «⌛ Настройка устарела, начни заново», как в `/new`.

Состояние настройки (`fav_id`, режим, дни, минуты) хранится в данных FSM; шаг 4 — состояние `SubEdit.waiting_for_time`.

## 3. Планировщик

Работает в существующем минутном цикле с догоном пропущенных минут (не больше 10). Время везде — `Europe/Samara`. Для каждой обрабатываемой минуты `M` выполняется:

**а) `schedule`** — как сейчас, плюс фильтр дней: `weekdays` = Пн–Пт, `weekends` = Сб–Вс.

**б) Планирование `remind`.** Подписка планируется, если одновременно:
- день подходит под `days`;
- `max(цель − 60 мин, 00:00) ≤ M < цель`;
- в `reminder_runs` нет записи `(sub_id, сегодня)`.

Действия:
1. Запросить рейсы: `dt` = сегодня, время начала = цель, `timeint` = 60.
2. Сайт не ответил → ничего не записывать (следующая минута повторит). Если `M ≥ цель − lead_min`, записать `skipped` и отправить «🚫 Не удалось получить расписание с сайта ИжГЭТ».
3. Взять первый рейс с отправлением `≥ цель` и следующий за ним.
4. Есть рейс → `fire_at = отправление − lead_min`, `status = planned`.
5. Рейсов нет → `fire_at = цель − lead_min`, `dep_time = NULL`, `status = planned` (отправится сообщение «рейсов нет»).

**в) Отправка.** Записи сегодняшнего дня со `status = planned` и `fire_at ≤ M`:
- рейс ещё не ушёл (`M < dep_time`) или `dep_time` пуст → отправить, `status = sent`;
- рейс уже ушёл (бот лежал) → `status = skipped`, ничего не отправлять.

Отправка идёт с тем же ограничением параллельности (5), что и рассылка `schedule`.

## 4. Сообщения

Напоминание (rich message):

> 🚶 **Пора выходить! «Дом → Работа»**
> 🚋 **1** отправляется в **8:03** — через 10 мин.
> Следующий — в 8:15.
>
> `[📋 Полное расписание]` `[💖 Поддержать автора]`

- Строка «Следующий» не выводится, если следующего рейса в окне нет.
- «через N мин» считается от фактического момента отправки (при опоздании будет меньше `lead_min`).
- «📋 Полное расписание» = `FavCallback(action='select', id=fav_id)` — тот же экран, что в избранном.
- Название маршрута экранируется (`html.escape`).

Рейсов нет: «😕 «Дом → Работа»: сегодня после 8:00 в течение часа рейсов нет.»

| `db/db.py` | Миграция колонок, `reminder_runs` и запросы к ней; `add_subscription` принимает `mode`, `days`, `lead_min`; удаление подписки/маршрута чистит `reminder_runs` |

## 6. Тестирование

### Автотесты

`pytest` в новом `requirements-dev.txt` (не попадает в Docker-образ), тесты в `tests/`:

1. **Парсер** на сохранённом ответе ижгэт.рф (`tests/fixtures/*.html`): список рейсов, «Нет рейсов», пустые ячейки; HTML-расписание не изменилось.
2. **`reminders.py`**: фильтр дней (все варианты × Пн/Сб/Вс), выбор первого рейса `≥ цели`, следующий рейс, `fire_at`, отсутствие рейсов, окно планирования около полуночи.
3. **Планировщик** с фиктивным временем и фиктивным `get_departures`: план в окне −60 мин; нет повторного плана после «перезапуска»; перепланирование после изменения подписки; опоздавшая отправка до ухода рейса; `skipped` после ухода рейса; сообщение при недоступном сайте; фильтр дней для `schedule`.
4. **Миграция**: БД со старой схемой `subscriptions` открывается, старые записи получают `schedule`/`all` и попадают в рассылку как раньше.
5. **Сценарий настройки** через `Dispatcher` с заглушкой Telegram: оба режима проходят шаги 1–4 и сохраняются с правильными полями; отмена на каждом шаге; устаревшее FSM.

Запуск: `venv/Scripts/python.exe -m pytest`.

### Ручная проверка в Telegram

Лучше на отдельном тестовом боте (новый токен от @BotFather в `.env`), тогда в эксперименте не участвует боевой бот и его база `izhGet.db`.

1. `/new` → любой маршрут → «Добавить в избранное».
2. `/favorites` → маршрут → «🔔 Подписаться» → «🚶 Напоминание» → «Каждый день» → «5» → время **на 70 минут позже текущего**.
3. Проверить подтверждение (и предупреждение, если указать ночное время, например `03:00`).
4. В течение минуты после «цель − 60» в `reminder_runs` появится запись `planned` с `fire_at` и `dep_time` — видно через `sqlite3 izhGet.db "select * from reminder_runs"`. Если время указано меньше чем через час, запись появится сразу после сохранения подписки.
5. Изменить подписку (например, минуты 5 → 10) после появления записи — `fire_at` пересчитается в течение минуты.
6. Дождаться напоминания; кнопка «📋 Полное расписание» открывает экран маршрута.
7. Перезапуск: перезапустить бота между планированием и отправкой — напоминание приходит один раз.
8. Старый режим: подписка «📋 Расписание» на ближайшую минуту приходит как раньше; с «Выходные» в будний день — не приходит.

## Вне рамок

- Разовое напоминание по кнопке под расписанием.
- Произвольные дни недели и ручной ввод минут.
- Несколько подписок на один маршрут.
- Живое положение транспорта (у источника данных его нет).
